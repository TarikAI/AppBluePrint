# Changelog

All notable changes to the app-blueprint skill. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The version is `TOOL_VERSION` in `app-blueprint/scripts/blueprint.py`.

## [Unreleased]

Work toward 2.0 on the `v2` branch. The tool reports version 1.9.N until 2.0.0 is released.

### Changed

- The tool is now a package: `scripts/blueprint.py` is a small launcher and the code lives in `scripts/bp/`. `python .blueprint/bin/blueprint.py <command>` works as before, and `init` copies the folder into `.blueprint/bin/`. Behaviour is unchanged from 1.3.0: a test compares the package against a frozen copy of 1.3.0 across 2,695 plans.
- `init --refresh-tool` upgrades an old single-file copy to the package. The copy is safe to interrupt: an incomplete or mismatched copy makes `guard` and the pre-write hook refuse (exit 2) and other commands exit 1 with the command that repairs it. It also copes with read-only files and with folders another program holds open.
- `doctor` shows whether a project's copy is the single-file or the package layout, and the plan's schema version.
- Incident records name the module file and function (`rules.py:120:validate`).
- `init` writes a version 2 `blueprint.json`. Version 1 plans keep working and are never rewritten; `validate` adds a `schema-v1` warning and `status` says so in one line. `status --json` and `export json` gain `features`, `milestones`, `tasks` and `unknowns` (empty for a version 1 plan).
- Proofs are stricter. Hashing ignores line-ending differences, so a 1.x proof of a CRLF file goes stale once. A file whose planned dependency changed is no longer verified. `verify --stale` lists what needs checking again.
- `guard` and the pre-write hook refuse (exit 2) whenever `.blueprint/blueprint.json` exists but cannot be loaded, whatever the reason: bad JSON, wrong encoding, a wrong shape or version. The one write still allowed is the fix to `blueprint.json` itself. 1.3.0 let writes through in some of these cases.
- The guard resolves every spelling of a path before deciding: mixed separators, case, 8.3 short names, `..`, trailing dots, `\\?\` and network-share forms on Windows.
- An unknown `BLUEPRINT_GUARD` value now blocks and says which values are accepted. 1.3.0 allowed every write.
- The `version` field is checked when the plan loads, not only by `validate`; a plan from a newer tool is refused with a message that says to update the tool.
- With `--json`, a plan that cannot load prints a JSON failure object on stdout as well as the text on stderr.
- `--help` lists the 2.0 commands after the existing ones. Commands that are not built yet say so and name the version that brings them.
- A `blueprint.json` the JSON reader cannot take (for example a number thousands of digits long) is the normal "not valid JSON" error everywhere, `validate --json` included, where it used to crash.
- Plans and state files nested as deeply as the JSON reader allows load again, as in 1.3.0 (1.9.1 crashed from about 450 levels). Anything deeper is a plain "nested too deeply" error.
- On Windows the guard also resolves alternate-data-stream spellings (`file::$DATA`, `file:x`) of a file that does not exist yet.
- Generated views carry a `Generated by blueprint.py render` line near the top. A view left without a record (after `state.json` was reset or merged) is adopted again when it has that line; any other file with a view's name is left alone, and only `render` fails on it. Views are never written through a hard link, symlink or junction, so a file shared with another place keeps its contents.

### Added

- `maintainers/design/v2-contract.md`: the contract for 2.0 (package layout, schema 2, evidence, the study engine, commands and workstreams).
- Plug-in points for the 2.0 modules (roadmap, features, unknowns, evidence, records): each adds its validation rules, views, status lines, map tabs and commands as a new file, without editing the core. A module that is present but broken is named in the error, and `doctor` still runs to report it.
- Generated views beyond `STRUCTURE.md`, `ROSTER.md` and `map.html` are tracked in `state.json`, removed when no longer produced, and never written over a file of yours with the same name.
- `.blueprint/bin/MANIFEST` lists the files of the copied tool, so an incomplete copy is detected and refused.
- `migrate` upgrades a version 1 blueprint to schema version 2 in one command. `--dry-run` shows what would change. The original is kept as `.blueprint/blueprint.v1.json` (never overwritten: a second, different original goes to `blueprint.v1.2.json`). The write is atomic, so an interruption leaves either the old plan or the complete new one. Plans it cannot write back faithfully (a number that is not finite, text that is not valid Unicode) are refused unchanged. The version 2 example is `references/example-blueprint-v2.json`.
- The repository now plans itself: `.blueprint/` at the repo root holds this project's own blueprint, with one owner per file. `maintainers/check_owned.py` checks that a branch changed only its owner's files before it is merged; it reads the plan and the tool from the base branch only and must be run with `python -I`.
- Test fixtures for the study lanes, all synthetic and built in code: APK, AAB, IPA, Electron asar and hostile archives (checked against the real `aapt2` and `dexdump`), and HAR files, source maps, bundles, captures, SQLite files and JADX, apktool and rea exports.

## [1.3.0] - 2026-11-18

### Changed

- `contracts` takes `--module ID` (repeatable) to list or write the README for chosen modules only; an unknown id exits 64, and a module without a path says so and exits 0. After writing, it reminds you to run the project's own tests, because a new README can break tooling that treats every entry in a folder as an item. SKILL.md step 8 says contracts are optional: list first, write per module when in doubt, then run the project's checks. The hint to add `--write` now appears only when something is left to write (c-55831b76).
- `validate` warns when an owner rule that is a bare folder name (`agents/`) matches that folder at the root and in a nested place. SKILL.md and `references/schema.md` now say that `docs/` matches any folder named docs and `/docs/` only the root one, and the example blueprint anchors its folder rules (c-5a1a611f).
- The minimum Python version is now 3.10 (3.9 reached end of life and is no longer on GitHub's Ubuntu runners). CI tests 3.10 and 3.12.

### Fixed

- `export codeowners` writes owner rules with forward slashes even when the plan used backslashes, so GitHub applies them.
- A malformed `blueprint.json` (for example `"files": ["oops"]`) no longer crashes with an unexpected error. Every command exits 1 and names each bad entry (wrong-typed text, list and `uses` fields included), such as `blueprint.json: files[0] must be an object (got string)`, then says to fix it and run `validate`. A section or field set to `null` counts as missing, and a missing key the code reads directly is filled with an empty value that `validate` then reports. A fuzz test (`test_plan_fuzz.py`) replaces each key of the example blueprint with ten wrong values and deletes it in turn (2,695 mutations); none crashes the functions behind `validate`, `sync`, `status`, `render`, `export` (csv, codeowners, agenticteam), `contracts` and `guard`, including the data scan and views. The reviewer also ran every mutation through the real command line in a git repository, 16 commands each, with no crash. Other shapes are not covered (c-62072a1b).
- Ignore rules and owner patterns written with backslashes (`src\legacy\`) now match like forward slashes.
- Tracked files in nested folders named `.claude`, `.codex` or `.agentic-team` (for example `tests/golden/codex/.codex/config.toml`) were invisible to `sync`. Those three default ignores now match the repo root only. An ignore rule never drops a file that is individually planned. It also never drops a path that matches a pattern, but only when every ignore rule that matches the path ends in `/` with no wildcard (`.claude/`, `src/legacy/`) and the pattern's glob names every folder of each such rule (`**/.claude/*.md` names `.claude`; `src/**/*.py` does not name `legacy`, so your own `ignore: ["src/legacy/"]` still wins). Wildcard rules such as `*.lock` yield only to individually planned files. This holds with and without git. `sync` says when default rules dropped tracked files (never counting `.blueprint/`) and records up to 20 of them as `ignoredTracked` in state (c-cf8599d6).
- Because `.claude/`, `.codex/` and `.agentic-team/` are now ignored at the repo root only, `guard` and the pre-write hook refuse unplanned writes into nested folders of those names, as they do for any other unplanned path (c-cf8599d6).
- A feedback test failed on Windows runners, where temp folders can appear in 8.3 short form; the path was still removed.

## [1.2.0] - 2026-11-06

### Added

- Data connections: `stores[]` and `resources[]` (tables, views, env vars, APIs, queues, buckets) and per-file `uses` with read or write access. `validate` checks them and flags writes to a resource owned by someone else.
- Static data scan in `sync`: reads SQL migrations (create, drop, rename) and Prisma schemas, and scans planned files for SQL, Supabase-style `.from()`, Prisma calls, env reads in five languages and API hosts. It reports undeclared tables and uses, missing tables, access mismatches and declared uses not yet in code. `sync --strict` fails on them.
- `db-check`: compares a live schema with the migrations, read-only and only on request. It reads a SQLite file directly, or Postgres from a `pg_dump --schema-only` file. It never stores credentials.
- Data views: a Data tab and a Data branch in the mind map in `map.html`, a Data section in `STRUCTURE.md` and data ownership in `ROSTER.md`.
- Learning loop capture: unexpected errors are recorded as incidents in `~/.app-blueprint` with paths removed (exit code 70). Also added `feedback`, `report` (prints a cleaned GitHub issue body) and `doctor` (finds out-of-date tool copies), and friction counts from `validate`. `APP_BLUEPRINT_NO_CAPTURE=1` turns all of it off.
- Maintainer tooling: `maintainers/learn.py` (harvest, promote, decide, scan-private, export, store sync, presets), the contract `maintainers/SPEC.md`, and four agents (`blueprint-harvester`, `blueprint-fixer`, `blueprint-reviewer`, `preset-scout`).
- GitHub issue forms, a pull request template, CI on Linux and Windows with Python 3.9 and 3.12, `CONTRIBUTING.md` and `learning/LESSONS.md`.
- `install.py --agents` installs the maintainer agents for Claude Code.
- `maintainers/make_example.py` regenerates the example project.

### Changed

- Project ids for the learning loop come from the git origin and the folder inside the repo, so one project on two machines counts once.

## [1.1.0] - 2026-11-06

### Added

- Mind map view in `map.html`: the app at the centre, branches by module, owner or phase, files coloured by status.
- Shared renderer `assets/mindmap.js`, inlined by `render` and copied into `.blueprint/bin` by `init`.

### Fixed

- `init --refresh-tool` now works when run from the copied tool in `.blueprint/bin`.

## [1.0.0] - 2026-11-06

### Added

- Initial release.
- `blueprint.py` CLI, standard library only: `init`, `validate`, `render`, `sync`, `status`, `owner`, `claim`, `mark`, `verify`, `guard`, `hook`, `contracts`, `export`.
- Generated views: `STRUCTURE.md` (annotated tree and module graph), `ROSTER.md` (owners and write lists) and `map.html` (interactive progress map).
- CODEOWNERS-style owner rules, last match wins, with a check for partial overlaps.
- Four stack presets: `vite-react-supabase`, `nextjs-prisma`, `pnpm-monorepo-docker`, `rust-agent-engine`.
- AgenticTeam export (`export agenticteam`) and team check (`validate --team`).
- Claude Code hooks: a pre-write guard and a post-write sync.
- Example project `examples/snag-desk`.
- Installer `install.py` for Claude Code, Codex and other agents.
